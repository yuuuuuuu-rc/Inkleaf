# 联网搜索工具设计

## 结论

应当增加，但它是“证据工具”，不是默认开启的聊天能力。对书籍阅读最有价值的场景包括：

- 考证历史背景、典故、人物和地名；
- 核验非虚构书中可能已经过时的事实；
- 找作者访谈、原始论文、数据或勘误；
- 比较不同译法与术语来源；
- 追踪书中观点在出版后的争论。

小说默认不自动搜索剧情相关内容，以防止剧透。

## 三种模式

- **关闭**：只允许书内检索。
- **询问后搜索（默认）**：AI 说明为什么需要联网，并显示准备搜索的关键词。
- **自动但防剧透**：只搜索背景事实和时效信息；涉及剧情、人物命运或后续章节时仍需确认。

## 工具边界

搜索工具由本机服务端调用，模型不能任意访问 URL 或文件系统。每次调用包含：

```json
{
  "query": "搜索词",
  "intent": "background | verify | primary-source | translation",
  "bookId": "当前书籍",
  "anchor": "当前章节或 CFI",
  "spoilerBoundary": "read-so-far",
  "privacy": "query-only"
}
```

默认只发送精简后的搜索词，不发送整段书文、整章内容或私人笔记。

## 结果呈现

回答中的证据分成两条轨道：

- **书内证据**：书名、章节、CFI 和短引文；
- **外部证据**：网页标题、发布者、日期、链接和访问时间。

外部网页不能悄悄覆盖作者原意。AI 必须明确说明外部材料是在补充背景、核验事实还是提出反驳。

## 实现建议

第一版采用独立搜索提供商适配层，而不是绑定某个模型厂商的内置搜索。这样现有 OpenAI 兼容接口、Gemini 兼容接口和本地模型都能使用同一套结果格式。

优先顺序：

1. 通用网页搜索 API；
2. 页面正文提取与来源去重；
3. 可信度和时效排序；
4. 原始来源优先（出版社、作者、论文、政府或机构）；
5. 搜索记录随对话保存，但密钥单独保存在本机配置。

第一版不应开放任意浏览器自动操作，也不应允许模型执行下载、登录、发帖或修改外部数据。
